# 知识库文档编写要求

检索按块匹配。一块里如果塞进多个问题和一长段截图识别文字，正确答案会被淹没，引用也会指到错误的段落。按下面写，切块才能把一个问题收成一块。

## 一个问题一个标题

每个问题单独用 Word 的「标题 2」或「标题 3」，例如「Q2.3 解除物料隔离」。不要只把 `【Q2.3】` 设成加粗的普通段落。加粗段落会被当成正文，和后面几问合并，最多约 1200 字。

Markdown 用 `##` / `###`。平台也会把另起一段、以 `【Q2.3】`、`Q2.3` 或 `问：` 开头的段落当成新的一块，但标题样式更稳。

## 一问一件事

一个问题只讲一件事。标题写成用户会问的话，例如「物料超期怎么解除」「先进先出卡控怎么做」，不要只用「问题 3」。

## 关键步骤写成文字

截图只作辅助。操作步骤、按钮名称、判断条件写在正文里。图片识别出的文字会单独成块，并且最多保留约 400 字，不能代替步骤说明。

## 怎么验收

仓库里的 `evaluation.go` 可以用一组「问题 + 标准答案」算 recall@5、引用是否指到正确段落，以及不该回答的问题有没有被误召回。把真实 FAQ 整理成这种用例后再看检索是否变准。评测本身不会改变线上切块。
