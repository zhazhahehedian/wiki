# 部门可见范围包含下级部门验证 · 2026-11-06

设计见 [飞书目录与发布 API · 2026-11-06 变更](../../superpowers/specs/2026-10-27-directory-and-publishing-api.md)。在公司 Windows 电脑完成。2026-11-06 已部署至公司内网服务器（镜像 20261106-8a78e4c-dirty，迁移 22→23，代码尚未提交）；升级脚本在临时库验证迁移并备份业务库后完成，`/` 与 `/healthz` 返回 200。

## 背景

发布到「信息管理部」的 MCP，该部门下级部门的成员看不到（管理员不受影响）。原规则只按本人直属部门 ID 精确匹配。用户确认情况属实，并同意放宽。

## 行为

成员归属 = 本人飞书 `department_ids` + 这些部门的全部上级（飞书「获取父部门信息」，本人 `user_access_token`）。可见判断代码和 SQL 未改，仍按 ID 精确匹配。无迁移、无新增飞书权限，无需重新授权。

| 成员位置（能力发布到 Engineering） | 结果 |
|---|---|
| Engineering 本身 | 可见 |
| Engineering 的下级部门 | 可见（新增） |
| 平级部门 | 不可见 |
| 上级部门 | 不可见 |

只影响读取：`department` 可见范围的能力市场与知识库。Owner、Admin、审核和知识库管理权限不变。

## 自动验证

环境：一次性 Docker 容器 `pgvector/pgvector:0.8.2-pg18`（仅绑定 127.0.0.1）、UUID 临时库、虚构账号。飞书是 `httptest` 模拟上游，**不是真实飞书**。

- `TestDirectoryPublishingIntegration`（真实 PostgreSQL + 模拟飞书）：下级部门成员的详情和列表都能看到，平级部门成员 404 且列表不含，上级部门成员的归属不含下级；部门知识库同样；原有过期、撤销和目录浏览不授予归属的断言保持通过。
- `internal/directory` 单元：上级合并去重、过滤根部门 `0` 和非法 ID；部门被隐藏时保留已查到的部门并用正常缓存；上游失败或超时保留直属部门并 30 秒后重试；部门调整后旧上级失效；ID 总数和分页有上限；浏览和选择部门不触发归属写入。
- `internal/infra/feishu` 单元：请求路径和参数、分页、空结果、错误码 40014 归为权限不足且不泄露上游信息。
- `go test ./...`：通过（带临时 PostgreSQL；本轮未带 MinIO 与知识库的临时库环境变量，相关用例跳过，上一轮[分片上传验证](../2026-11-06-mcp-resumable-upload/README.md)已跑过，本次未改这部分）。

## 未验证 / 发布边界

- **未用真实飞书账号验证。** 飞书文档说明，用户令牌只返回该用户可见的上级部门。如果企业策略对某成员隐藏了上级部门，这个成员仍看不到发布到该上级的能力，平台会记录日志 `department ancestors not visible`，但不报错。

部署后验收（可用 Irene Yu 的账号）：

1. Irene 打开能力市场后，查看设置页「飞书部门 ID（含上级部门）」，应多于一个，且包含这些 MCP 的部门 ID。
2. 能力市场能看到 Leason 发布到信息管理部的 MCP，并能下载。
3. 其他部门的账号仍看不到。

如果第 1 步仍只有直属部门，就是被组织架构可见范围挡住了：调整该成员的可见范围，或改用应用身份查询上级部门（需另行决定，并需要应用的通讯录权限）。
