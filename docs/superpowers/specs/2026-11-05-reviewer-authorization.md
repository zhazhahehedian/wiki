# 独立审核员与审核资格管理

状态：2026-11-05 用户已确认：新增独立审核员，第一版可审核全平台 MCP / Skill，允许自审。本文规定本轮实现范围，不表示已授予真实用户权限或已部署。

## 改动前的问题与代码边界

- 改动前平台只允许 Admin 审核 MCP / Skill，Owner 可提交；审核队列、待审详情、Skill 文件和治理操作均依赖 Owner/Admin 身份边界。
- “部门授权”页面只维护历史可信部门名称，无法授予审核资格。飞书职位、目录可见范围和平台审核权限是不同概念。
- 原审核事务在读取身份后锁定能力；角色管理上线需增加角色锁来明确审核与撤权的并发顺序，不能只修改前端入口。
- 发布 API 与浏览器复用部分详情、下载服务，新增审核读取权限不能自动扩展 Bearer 凭证的能力。

依据：[基础规格 §5、§7.1](2026-09-04-capability-hub-design.md)、[飞书目录与发布 API](2026-10-27-directory-and-publishing-api.md)、`backend/internal/repo/governance_repository.go`、`backend/internal/registry/governance.go`、`frontend/components/hub/governance-pages.tsx`。

## 已确认的产品决定

- 新增独立 Reviewer（审核员），不通过给领导授予 Admin 来实现审核职责。
- 管理员授予、撤销审核资格；审核员可查看必要待审材料并通过、驳回。
- Reviewer 不隐含平台管理权限；管理用户角色、全平台审计、强制上线、管理性下线和覆盖可见范围仍属于原有 Admin 边界。审核员同时是 Owner 时，保留自己的 Owner 权限。

## 审核范围与自审

- Reviewer 与 Admin 均可审核全平台 MCP / Skill 待审队列，不按部门筛选授权，不涉及父子部门继承。
- Reviewer 与 Admin 均允许审核自己的发布，使用同样的发布校验并记录实际操作者，不宣称双人审批。
- 授权与飞书职位、通讯录可见范围及部门成员归属无关。

## 交付范围

1. 管理员在用户管理页按姓名或 Open ID 查找已登录用户，查看、授予或撤销审核资格；变更需填写原因，携带修订号，并与审计原子保存。第一版复用已有登录用户列表，人员身份以飞书 Open ID 为准。
2. 登录用户能看到自己的角色和审核范围。Owner 在提交页面能看到适用于本次提交的可审核人员或明确范围；无人可审核时显示提示。名单表示有资格处理共同队列，不表示已指定某个人负责。
3. 审核员看到与授权匹配的待审队列，可读取待审版本及必要的当前上线版本对照、Skill 文件与拟发布可见范围，支持通过与带理由驳回。审核资格不开放无关草稿、历史版本或私有能力。
4. 审核完成后刷新队列和详情；失去审核权限时显示明确错误并刷新身份。普通浏览、知识库、产品凭据、账号密钥和发布 API 继续执行各自权限规则。
5. 保留既有 bootstrap 单例初始化；不通过修改环境变量或重置 bootstrap 增加管理员。本功能的授权入口只管理审核资格。

## 服务端与并发要求

- 迁移 `0020_platform_reviewers.sql` 为 `platform_profiles` 追加 `is_reviewer`（默认 false）。管理员原有权限不依赖此标记；更改它沿用 profile 修订号。
- `PUT /api/v1/governance/profiles/{openID}/reviewer` 接收必填 `is_reviewer`、`revision` 和非空 `reason`，仅管理员可调用；不接受其它角色字段。授权与撤销写入 `set_reviewer` 审计。
- `GET /api/v1/governance/me` 与管理员 profile 列表增加 `is_reviewer`；`GET /api/v1/governance/reviewers` 对登录用户提供分页审核人名单，仅包含 Open ID、姓名及管理员标记。
- 详情增加 `can_review` 和 `is_review_view`。非 Owner/Admin 审核视图只在 `in_review` 开放，版本限定为待审版本和仍上线的当前版本。非 Owner/Admin 完成审核后仅返回操作回执，前端返回队列并清理该能力的审核缓存。

- 队列查询、详情投影、文件预览/下载和通过/驳回必须分别执行服务端鉴权；前端入口由服务端返回的角色及当前动作权限决定。
- 审核读取只提供此次审核所需版本。Owner/Admin 继续按既有权限读取，不能用 Reviewer 标记替代 `is_admin`。
- 授权变更与审核操作采用一致的锁顺序，在提交前核对持久授权、能力状态、`revision` 和 `version_id`。撤权事务先完成则审核失败；审核先取得必要锁并完成则撤权随后生效。
- 撤权完成后的新请求不能依赖登录时保存的旧角色。审核写入、发布快照切换与审计仍在同一事务完成；旧页面重复提交及并发审核不能产生第二次发布。
- 浏览器写入保留 Session / Origin / CSRF；发布 API 保留账号绑定及原有 scope 上限，不获得 Reviewer 专属读取或审核能力。
- 追加迁移并再生成 sqlc，保留既有数据；只在隔离数据库验证升级与回退。
