# 飞书目录与能力发布 API

本轮范围：当前登录人可见的部门/人员选择，以及账号绑定的 MCP / Skill 发布 API。保留现有部署、登录、模型、落地页及指南改动；不涉及服务器迁移、适用工具标注或部署。

## 设计

- 目录请求使用当前账号的 `user_access_token`，经已有 OAuth 加密存储与刷新服务取得。分页浏览直属子部门、直属人员，服务端验证所选 ID；不使用应用通讯录范围替代用户可见范围，不保存全公司通讯录。
- 实际账号验收发现根部门 `0` 可被企业策略隐藏。仅在根节点无访问权限时，以本人部门 ID 逐个通过用户令牌确认可读后提供入口，返回 `limited_root` 并在选择器提示范围；非根节点拒绝仍返回错误。该查询不更新成员归属缓存，不代表枚举出全部可见组织。
- 能力与知识库的部门关联新增 `department_id`（飞书 `open_department_id`），`department` 为显示名称快照；人员继续使用 `open_id`。能力编辑、管理员可见范围覆盖、知识库编辑共用选择器。已有字符串部门记录原样保留，只有未迁移记录继续使用原管理员核实的部门规则。新关联不能从名称推断 ID。
- 本人的真实部门来自单独查询本人的 `department_ids`，缓存最多五分钟。目录浏览结果绝不写入成员归属；缺少权限、过期或上游失败时关闭新增部门 ID 授权，Owner/Admin 和原有规则仍由服务端判定。多部门按精确 ID 匹配，不隐式扩展祖先/子部门。
- API 凭证绑定创建它的登录账号；随机 256 位秘密仅返回一次、数据库只存 SHA-256 摘要。必填到期时间（最长 365 天）、显式 `capabilities:read/write/submit` 权限；支持列出、撤销和审计。没有代用户绑定、凭证管理或管理员审核权限。
- `/api/v1/open/capabilities` 仅接受 Bearer；复用现有注册、更新、文件上传、版本冲突和审核服务。`submit` 仅进入审核，审核仍在站内执行；已发布能力通过 `new-draft` 后更新版本。浏览器接口保留 Session/Origin/CSRF，不因新增 Bearer 而绕过。
- 站内 `/hub/api-docs` 提供凭证管理、请求/响应、错误码与 MCP、Skill、更新和提交示例。Skill 沿用 multipart 完整包上传（最多 50 文件、10 MiB、路径和发布格式校验）。

## 验证与交付边界

追加迁移仅在一次性数据库执行 up/down/up；验证摘要、账号隔离、过期/撤销、权限拒绝、审核和版本冲突、飞书分页/错误/真实归属隔离、前端测试与构建。真实飞书后台增权和账号重新授权由管理员操作，模拟上游不能代替真实账号验收。
