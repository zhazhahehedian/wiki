# 知识服务与外部应用检索设计

日期：2026-09-19。状态：K1 开发实现已接入，隔离基础设施及 fixture 验证已开展；真实 embedding 和真实账号验收尚未完成。实现契约及保守解析边界见 [API 文档](../../knowledge-api.md)。

本设计落实能力中心主 spec 的 D12，替代“不做知识库”和退役文档摄入、chunks/embedding 的相关决定。已实现的能力市场、治理、Skill 创建与游乐场继续保留。

## 1. 定位与职责

平台定位扩展为 **能力市场＋知识服务平台**：知识库提供事实资料，Skill 提供做事方法，MCP 提供工具操作。外部系统指经授权接入的业务应用，不意味着匿名开放或商业化 SaaS。

| 本平台 | 接入的业务应用 |
|---|---|
| 知识库、文档管理、解析、切分、索引和检索 | 聊天页面、会话历史和多轮问题整理 |
| 应用凭证、知识库授权、权限过滤和审计 | 提示词组织、选择模型、生成回答和流式展示 |
| 返回可追溯片段、文档版本与引用位置 | 展示回答及来源引用，处理检索为空或不可用 |

调用链：用户提问 → 业务应用后端调用知识检索 API → 平台返回授权知识片段 → 业务应用调用模型回答。

本阶段不恢复原 ReAct Agent、知识聊天产品和旧会话页面，不在线执行 Skill，不代理第三方 MCP 运行时。内置检索是本平台自己的服务，不受“注册中心不进第三方 MCP 调用链路”的限制。

## 2. 开发顺序与第一期范围

新增 **K1 知识服务基础闭环**，作为下个 session 的优先工作。既有 D（MCP 凭证/发现）、E（健康检查）仍在后续队列；K1 的应用检索凭证从原“机器 token 延后”中提前实施，不等同于完成 D。

K1 必须包含可操作页面、持久化、服务端授权和可供外部应用调用的 API：

1. 知识库创建、编辑、可见范围与成员管理；管理者为 Owner/Admin，浏览与检索权限独立判断。复用可信部门身份，不接受客户端自报部门。2026-10-27 增补：新部门关联使用飞书 `department_id`，选择器按个人可见范围查询，授权以本人真实部门 ID 校验；历史未绑定 ID 的记录保留原可信名称规则。见[目录与发布 API 设计](2026-10-27-directory-and-publishing-api.md)。
2. 文档上传、列表、处理状态、失败原因、重试、版本更新和删除；首批支持 TXT/Markdown，并复用和验证既有 PDF/DOCX 解析器。扫描件 OCR、更多格式、外部同步另列后续，未支持格式上传时明确拒绝。
3. 使用 River 异步解析、切分、embedding 和索引，页面能区分等待/处理中/可检索/失败。提供知识库内的检索测试页，展示命中片段、来源和版本，不调用回答模型。
4. 应用管理：Admin 创建/禁用应用、发放/撤销/轮换凭证，显式授予特定知识库的检索权限，展示调用概况与安全审计。
5. 外部检索 API、接入文档和可运行调用示例，完成“上传 → 就绪 → 授权应用 → 检索出片段”的真实闭环。

**2026-09-22 用户确认：检索优化提前进入 K1**。平台承担单次问题改写、原问题与改写问题向量召回、中文关键词混合检索和重排序，以便内部应用试用。原问题始终保留，模型失败有明确降级标识；权限过滤覆盖每条召回路径，重排不修改引用。具体配置、评分和预算见 [API 文档](../../knowledge-api.md)。真实模型质量验收仍是独立门槛。

2026-10-26 真实模型部署验证补充：含显式否定或限制词的问题，在发起改写前确定性保留原文，避免模型删掉被排除的对象；此时状态为 `unchanged`，不宣称调用过改写模型。普通问题继续模型改写，非法输出或超时仍明确降级，原文检索与语义重排始终保留。

**K2 来源同步**：在 K1 稳定后接回飞书云文档同步，Wiki 仅解析到受支持的云文档，不接入 Sheets/多维表格；处理来源授权撤销、删除、增量和失败恢复。后续检索优化按试用评测继续迭代，不预设新框架依赖。

**K3 可信用户委托**：接入统一身份或可验证的短时用户令牌，支持应用代表用户查询个人/部门资料。K1 不提供未经验证的 `user_id`/`department` 请求字段作为授权依据。是否提供 MCP 检索封装留到 REST API 闭环之后决定。

### 2.1 文档来源和质量边界（用户确认）

定位为以文档为中心的知识检索服务，先沿用现有 Go 服务部署，通过独立 API 和应用授权划定服务边界，不要求本期拆分微服务。

- K1 仅接收 TXT、Markdown、DOCX、可可靠提取文字的 PDF；Word 指 DOCX，旧 DOC 不隐式纳入。K2 接飞书云文档及指向该类型的 Wiki 链接。
- Excel、CSV、飞书电子表格、多维表格不进入 K1/K2 通用文档摄入白名单。未来按独立结构化查询能力评估，不把转成文本后的向量召回当精确筛选、关联或汇总。
- 文件扩展名不是质量保证。校验实际格式和内容；保留标题、章节、段落、列表等结构。文档内的说明性表格可以纳入，但须保留表头、单位、适用条件和章节上下文；无法可靠还原时明确提示。
- 提供解析预览与质量诊断，区分空内容、乱码、漏页/页提取失败、未支持的图片和嵌入内容。发现缺失时不得静默标记完整成功；正文缺失或明显损坏阻止发布新索引版本，非关键未支持内容须显式展示警告和范围。扫描件需 OCR 时明确拒绝或标记暂不支持，不生成空索引。
- 按文档结构切分，片段保留标题路径、实际来源位置和不可变版本；PDF 保留页码映射，DOCX/Markdown 使用可验证的章节或段落位置，不编造页码。检索结果与预览能追溯同一版本。
- K1 就建立固定的业务问题评测集，覆盖正确片段、引用定位、跨段上下文、制度中的表格、无答案和相似但不适用内容。记录检索配置、数据/索引版本和 Recall@k、引用正确性、无答案误召回等结果，在实现阶段明确样本与通过标准；不能以 HTTP 200 或返回非空片段替代质量验收。混合检索/重排是否提前采用由评测缺口决定，不为保留分期而跳过 K1 质量问题。

## 3. 数据与权限边界

- 人员管理接口使用现有飞书 session、CSRF 和 Origin。浏览器的检索测试按当前用户身份鉴权，不借用应用 token 绕过权限。
- 外部 API 使用独立应用主体与 Bearer 凭证，至少具有 `knowledge:search` scope；按显式应用—知识库授权限制资源，不使用浏览器 Cookie 或 Owner UUID 冒充调用者。
- K1 授权对象是可明确整体共享给该应用的知识库。浏览器侧“全公司可见”不自动授予所有应用访问权；用户私有资料及具有不一致来源 ACL 的文档不得直接并入应用共享库。
- 应用凭证只在创建/轮换时展示一次，高熵随机生成，服务端保存不可逆摘要及可识别前缀，支持到期、撤销、禁用和最后使用时间。摘要凭证与可回取的 MCP 共享凭证保险箱是不同用途，不复用可解密存储路径。
- 调用者只能请求授予的知识库；明确请求中混入未授权库时整次拒绝，不静默返回部分结果。检索过滤必须在候选获取阶段落实，不能先全库查询再靠前端过滤。
- 文档删除、知识库撤权、应用禁用/凭证撤销后，新请求应立即不可见；在途请求返回前复核授权及文档可见状态，失效则拒绝或剔除失效片段。索引物理清理可以异步，逻辑不可见不能等待清理完成。
- 文档更新采用独立待处理版本，完整索引后原子切换可检索版本。失败保留原有效版本并明确展示“更新失败、旧版仍可用”；用户要立即隐藏旧内容时可删除/停用。禁止新旧片段混合、旧任务覆盖新版本。
- 文档内容是数据，不是系统指令；接口不执行文档内命令。日志不保存凭证、原始问题或文档全文，记录应用/知识库标识、请求编号、耗时、结果数量、状态和安全错误码。

## 4. API 初版契约

机器调用：`POST /api/v1/knowledge/search`，`Authorization: Bearer <application_token>`。

```json
{
  "knowledge_base_ids": ["kb-id"],
  "query": "报销需要哪些材料？",
  "top_k": 5
}
```

- `knowledge_base_ids` 必填且去重，1–10 个；`query` 为非空文本，最多 4000 字；`top_k` 默认 5、范围 1–20，为所有所选库合计上限。请求体、片段长度、总响应量另设服务端上限，不能仅依赖 top_k。
- 返回 `request_id` 和 `matches`；每项至少包含 `knowledge_base_id`、`document_id`、`document_version_id`、`chunk_id`、`title`、`content`、`score`、`locator`（适用时页码/章节）与可用的来源信息。分数是排序信号，不标成回答正确率。
- 引用对应本次实际检索的不可变版本。来源链接不包含对象存储密钥、磁盘路径或绕过鉴权的下载地址；不能提供外部可访问链接时仍返回文档标识和定位信息。
- 成功但无命中：200、空 `matches`，不虚构答案。无效/过期凭证为 401，scope/库授权不足为 403（不暴露无权对象详情），格式错误为 400，限流为 429，检索依赖不可用为 503，超时为 504；错误带请求编号，不返回底层凭证或原始异常。
- 提供按应用的配额/速率与并发约束、请求超时和取消传递。若所选库存在待处理/失败文档且没有任何可检索版本，返回 409 `knowledge_not_ready`，管理页面可查看具体处理状态；已就绪但无匹配或真正空库返回 200、空 `matches`，避免把索引失败当正常空结果。
- 多轮问题改写由业务应用负责。第一期接口不接收聊天历史，不生成最终答案，不绑定某个聊天 SDK。

人员管理/检索测试与机器 API 分别挂载鉴权中间件。具体 CRUD 路由及错误结构在实现开始时与现有项目风格收敛，不能靠重新开启 `legacy=true` 暴露整套旧接口。

## 5. 复用与迁移

现存 `Retrieval.Retrieve`、`OwnedVectorSearch` 按个人 Owner 隔离，必须适配服务端解析出的用户/应用授权范围；不能把任意应用 token 映射为 Owner 后直接调用旧方法。优先复用解析器、River、MinIO、embedding、切分、快照和引用组件。

开发前盘点实际表结构、旧知识库归属和索引维度。保留旧表和旧数据；停止执行历史 chunks/embedding 退役计划。权限、应用凭证、文档版本等 schema 改动采用增量 goose migration，并重新生成相关 sqlc。旧数据保持私有且不自动授权外部应用。

知识库服务使用平台受控的 embedding 配置。不得借用某个人的游乐场密钥或将生成模型配置视为 embedding 能力验证。模型/维度/索引版本要可追踪，维度变化不能混写旧索引，采用重建并切换策略。

2026-10-26 部署选型：用户选择北京地域的 `tongyi-embedding-vision-plus-2026-03-06`，使用 DashScope 原生接口与显式 1024 维输出。K1 仍只发送解析后的文本，不扩大为图片/视频摄入。为适配模型单条 1024 token 限制，完整 embedding 输入（含标题）采用保守的 768 UTF-8 字节预算，不把它宣称为精确 token 计数；切片保留来源位置和重叠，超限表格或标题明确阻断，绝不静默截断。搜索原问题超限返回参数错误，超限改写回退原问题。旧 OpenAI 兼容服务保留原有切分上限。DeepSeek 官方接口的 `deepseek-flash` 用于问题改写及重排时显式关闭 thinking，并要求 JSON 输出；现有超时、授权复核与降级边界不变。真实模型验收仍需单独完成。

环境沿用根 `.env` 中的远程 PostgreSQL/MinIO；连接地址与密钥不写入文档。本次只读检查已确认数据库迁移为 15、新市场 SQL 可执行，这是时间点证据，下次需复核；Docker 不是访问远程服务的前置条件。任何建库/迁移/回滚/写入测试须明确目标和授权范围，不因配置存在就作用于业务库。

## 6. 验收标准

1. Owner 在真实页面建库、上传至少一种文本和一种已支持的复杂文档，等待完成，能在检索测试页看到正确片段、版本和引用位置。
2. Admin 为应用 A 授权库 A；应用 A 的实际 HTTP 请求只返回库 A 的资料。应用 B、未授权库、伪造用户标识、失效凭证均被正确拒绝。
3. 更新失败保留旧有效索引；更新成功原子切换；删除、撤权、禁用以及并发更新下无过期片段泄露或索引复活。
4. 从外部调用示例真实发出请求并取得引用；embedding 真实调用、数据库、MinIO 的实际验证与模拟测试分别记录。尚不可用的外部依赖标明阻塞，不冒充通过。
5. 页面含空态、等待、失败与重试；文档页能看到可检索版本。限流、取消、依赖失败和日志脱敏有针对性回归。
6. 能力市场、Skill 复制/保存、现有治理和游乐场不被重新接回的旧路由破坏。K1 的完成不自动标记 D/E 或 K2/K3 完成。
7. 文档白名单在服务端生效；扫描件、页提取失败和正文损坏不会静默入库为完整成功，解析预览与引用定位一致。固定业务问题评测具有可重复的输入、预期证据和结果记录；真实 embedding 质量验证与 fixture 验证分别报告。
