2026-09-06 用户确认接入女娲思路，引导普通用户创建 Skill，并授权继续开发。此决定将轻量生成引导从后续产品提前实施；保留 B 草稿闭环与全部未提交改动，不启动 C 治理，不做公司模型真实联调。

## 产品与实现契约

- 新入口 `/hub/registry/create-skill`：默认通用工作流程模板；另有基于女娲方法适配的“专家思维/方法论”模板。支持描述需求、追问补充、粘贴或导入文本素材、迭代生成、预览编辑、保存 Owner 草稿。
- 复用用户加密模型连接及 OpenAI/Anthropic 代理。后端固定模板，浏览器只能提交 user/assistant 历史，不能替换 system；对话和素材仅存页面内存，离开页面清除。一次一轮，沿用 45 秒上游限时，支持取消，无自动模型重试和后台作业。
- POST `/api/v1/skill-builder/turn` 接收模式/模型/历史/素材/当前编辑草案；收集有上限的模型输出，严格解析 JSON，先校验再返回；无效/截断/取消的响应不替换之前的有效草案。
- 结构化草案：slug、name、description、instructions、files。平台从 slug/description 构造 YAML frontmatter，用户编辑正文、元数据和附件；最多 10 个文本附件、每个 32 KiB、合计 128 KiB。校验包路径、扩展名、UTF-8 和 Markdown 相对文件链接。只生成文本，不执行 Skill/脚本，不发起 MCP 调用。
- POST `/api/v1/skill-builder/drafts` 在服务端再次校验草案，生成 SKILL.md+附件，调用现有 registry 保存为 1.0.0 Owner 草稿。名单/可见范围设置保留到已有编辑页，首次保存默认 org 配置但草稿仍仅 Owner 可见；保存失败保留编辑内容，重复 slug 返回冲突，不覆盖既有条目。
- 不修改数据库 schema，不提高现有 playground 上限，不新增依赖。新增 create-skill 保留 slug，防止与静态页面冲突。
- 女娲只作为受版本管理的生成方法/模板，固定引用上游提交并保留 MIT 归属；原版研究 Agent/字幕下载和联网检索不属于此次范围。

## 实施结果

- 后端：`internal/skillbuilder` 内置模板/生成协议/文件校验，HTTP 两个端点及 server 装配。沿用用户加密模型连接、出站地址限制、两种协议和取消，不改变 playground 服务接口。
- 前端：注册中心、我的发布及手动新建页提供入口；创建页含双模板、需求对话、素材粘贴/导入、正文/附件编辑和预览。当前编辑草案作为后续生成上下文，允许模型修复未完成的编辑；只有有效结果替换草案，保存时再次完整校验。
