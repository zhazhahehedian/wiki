# Skill 引导创建 · 实施计划

2026-09-06 用户确认接入女娲思路，引导普通用户创建 Skill，并授权继续开发。此决定将轻量生成引导从后续产品提前实施；保留 B 草稿闭环与全部未提交改动，不启动 C 治理，不做公司模型真实联调。

## 产品与实现契约

- 新入口 `/hub/registry/create-skill`：默认通用工作流程模板；另有基于女娲方法适配的“专家思维/方法论”模板。支持描述需求、追问补充、粘贴或导入文本素材、迭代生成、预览编辑、保存 Owner 草稿。
- 复用用户加密模型连接及 OpenAI/Anthropic 代理。后端固定模板，浏览器只能提交 user/assistant 历史，不能替换 system；对话和素材仅存页面内存，离开页面清除。一次一轮，支持取消，无自动模型重试和后台作业。2026-09-08 按真实生成失败反馈，将共享模型流式调用总时限从 45 秒调整为 5 分钟，响应头等待上限从 15 秒调整为 60 秒，HTTP 客户端兜底为 6 分钟；游乐场流式对话与 Skill 生成两条 POST 路由的外层时限同步调整为 6 分钟，其余路由仍为 60 秒，模型列表发现仍为 20 秒。Skill 页面等待完整输出校验后一次性展示结果，生成期间显示动画与已等待时间，不展示虚构百分比；超时、响应提前结束、上游 HTTP 拒绝与无效草案分别返回可区分错误，失败保留输入与原草案。
- POST `/api/v1/skill-builder/turn` 接收模式/模型/历史/素材/当前编辑草案；收集有上限的模型输出，严格解析 JSON，先校验再返回；无效/截断/取消的响应不替换之前的有效草案。
- 2026-09-08 补充生成诊断：识别模型明确返回的输出长度上限结束原因，区分空响应、未闭合 JSON、JSON 语法、草案结构、文件校验和响应体积超限；返回具体提示与安全原因码/字节数，日志关联请求编号，不记录模型原文或原始解析错误。不自动重试，也不放宽草案校验。
- 2026-09-08 用户报告预设需求成功、自定义或带参考说明需求出现上游 503：增加上游机器错误码白名单分类，未知错误仅显示已知状态，不按内容复杂度猜测原因。错误体限 16 KiB、读取限时 2 秒。记录生成请求的模型、输入字节数、对话条数、预算和耗时，保留请求编号关联，不落盘对话、素材、草案正文或上游错误原文。长参考说明、多轮对话和当前草案通过两种协议的本地传递回归；真实 503 原因仍需失败输入和上游诊断核对。
- 2026-09-08 用户明确以 Opus 5、Kimi K3、GPT-5.6 等新一代模型为主要使用范围。Skill 默认输出预算从固定 8192 提高为 65536；请求增加可选 `max_tokens`（1–1048576），页面“生成设置”可调高或调低，未传值的客户端也使用新默认值。共享模型代理与游乐场参数输入同步接受到 1048576；这是平台请求上限，实际范围仍由模型/中转服务决定，不按模型名称猜测、不静默降额或自动重试。预算仅存页面内存，草案文件与请求大小校验保留。
- 对外 OpenAI 兼容请求使用当前 `max_completion_tokens` 字段，Anthropic 使用 `max_tokens`；浏览器到本平台的参数名保留 `max_tokens`，服务端按显式协议转换，不向上游同时发送两个字段。Skill 生成不再强制 `temperature=0.3`，使用模型默认采样行为，以兼容 Opus 5 等不接受自定义温度的模型。Anthropic 游乐场未显式设置输出预算时也使用 65536；OpenAI 未显式设置时仍省略预算，由模型决定。思考内容不拼入草案 JSON，推理消耗可能计入输出预算。
- 结构化草案：slug、name、description、instructions、files。平台从 slug/description 构造 YAML frontmatter，用户编辑正文、元数据和附件；最多 10 个文本附件、每个 32 KiB、合计 128 KiB。校验包路径、扩展名、UTF-8 和 Markdown 相对文件链接。只生成文本，不执行 Skill/脚本，不发起 MCP 调用。
- POST `/api/v1/skill-builder/drafts` 在服务端再次校验草案，生成 SKILL.md+附件，调用现有 registry 保存为 1.0.0 Owner 草稿。名单/可见范围设置保留到已有编辑页，首次保存默认 org 配置但草稿仍仅 Owner 可见；保存失败保留编辑内容，重复 slug 返回冲突，不覆盖既有条目。
- 不修改数据库 schema，不新增依赖。生成时限和输出预算采用上述 2026-09-08 调整。新增 create-skill 保留 slug，防止与静态页面冲突。
- 女娲只作为受版本管理的生成方法/模板，固定引用上游提交并保留 MIT 归属；原版研究 Agent/字幕下载和联网检索不属于此次范围。

## 实施结果

- 后端：`internal/skillbuilder` 内置模板/生成协议/文件校验，HTTP 两个端点及 server 装配。沿用用户加密模型连接、出站地址限制、两种协议和取消，不改变 playground 服务接口。
- 前端：注册中心、我的发布及手动新建页提供入口；创建页含双模板、需求对话、素材粘贴/导入、正文/附件编辑和预览。当前编辑草案作为后续生成上下文，允许模型修复未完成的编辑；只有有效结果替换草案，保存时再次完整校验。
- 保存复用 B 的事务与对象存储处理，版本为 1.0.0，Owner 由当前会话取得。相同 slug 冲突时不会覆盖既有能力。目录导航取消查询不再记录成 500。
- 验证：后端全量测试和 server 构建、前端 144 项测试/typecheck/build、隔离云 PostgreSQL/MinIO 与 OpenAI/Anthropic 模拟上游、Edge 桌面/移动完整交互通过。详见 [验证记录与截图](../../verification/2026-09-06-skill-builder/README.md)。
- 代码未提交或推送。未改现有开发数据库或常驻服务；本功能无需新迁移，使用 B 能力时开发库仍需通过项目迁移入口升至 0014。临时测试服务/库/对象清理，原工作区未提交改动保留。公司模型真实联调和生成质量验收继续暂缓。
